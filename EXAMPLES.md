# Examples

Buildable example modules, each a single file. Every module name in the table below
is relative to the `CatCrypt.Crypto.` prefix: build one with
`lake build CatCrypt.Crypto.<module>`, or elaborate its file with
`lake env lean <path>` to run its `#eval`s. Start with
[GETTING_STARTED.md](GETTING_STARTED.md) and [DEMO.md](DEMO.md); this is the fuller
index.

| Module | What it shows |
|---|---|
| `SecureCompilation.CompilerHelloDemo` | A routine written by hand as a term of the scalar front's `Thir` input type, lowered by the front and compiled to AArch64, with the assembly printed. |
| `SecureCompilation.CompileFromHaxLinkExample` | An outer program `let r = sha256_sigma0(inp[0]); ret r`, written in Lean as a `Thir` term (not a hax extraction) and lowered by the scalar front, with the front-compiled SHA-256 σ₀ kernel `ThirToComFront.sigma0Com` inlined at its one call (`linkedSigma0Com`). `linkedExample_correct` proves, with no hypothesis, that the linked program denotes `x.rotateRight 7 ^^^ x.rotateRight 18 ^^^ x >>> 3` for every 32-bit `x`. |
| `SecureCompilation.MultiBackendDemo` | A register program `r := a·b + a` and a one-multiply `Com` (`mulCom`), each compiled to AArch64 and RISC-V. For each backend, a theorem equates the machine block's run with the scalar selection's denotation of the register program (`kernel_arm`, `kernel_riscv`, `mulCom_arm`, `mulCom_riscv`); `mulCom_riscv_e2e` states that the RISC-V block leaves `Com.denote mulCom V` in the result register, and `ScalarLinNeutralDemo.com_arm_e2e` is the AArch64 statement for every supported `Com`. |
| `SecureCompilation.RelationalFrontMachine` | A `ZMod 251` add and a GF(2⁸) multiply given as Lean specifications, related through a `Com` written in Lean (not generated by the relational front) and the scalar backends to the result register of the compiled AArch64 and RISC-V blocks. |
| `SecureCompilation.RelationalFrontCurve25519` | Curve25519 base-field add and multiply proved equal, through a 4×64-bit limb encoding, to the Lean list functions `mlAddModK` and `mlMulMod`; no code is compiled. |
| `Jasmin.Examples.JincParserDemo` | The import direction: a hand-written Jasmin `.jinc` leaf parsed into the IR and inspected. |
| `SecureCompilation.MLIR.VectorDialect.LoweringAVX512Demo` | A SIMD vector-dialect kernel lowered to AVX-512. |

[DEMO.md](DEMO.md) and [README.md](README.md#the-guarantees) name the correctness
theorems behind these modules with their fragments and hypotheses.
`lake env lean AxiomAudit.lean` prints the axioms of the theorems that file lists;
[BUILDING.md](BUILDING.md#check-axioms) explains how to check another theorem and gives
the command that lists the package's declared axioms.
